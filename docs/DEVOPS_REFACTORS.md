# DevOps refactors

**Goal.** Infra deploys LEZ from our images by setting only the things that really differ per deployment, passed as flags or env:

- ports and listen addresses
- key locations
- channel id and funding key
- bootstrap peers

Everything else (config, genesis) is static and ships with the image.

**Inputs.**

- Meeting with infra on 2026-10-14 (decisions below).
- How [infra-logos](https://github.com/status-im/infra-logos) deploys LEZ today: `ansible/roles/logos-execution-zone`, `ansible/vars/lez/*.yml`, `ansible/files/lez/<env>/`.

## Decisions from the infra meeting

**Config layering.**

- Three layers, in increasing priority: config file, then env var, then CLI flag.
- Flags fail explicitly when misnamed. Env vars fail silently. Every flag gets a matching env var, named mechanically from the flag.
- Defaults baked into code hide differences between deployments. Ship an explicit default config file with the image instead.

**Static parts.**

- The sequencer config, indexer config and blockchain config are static.
- Genesis is baked into the binary. A separate genesis file can override it.

**Overrideable parts.**

- Listening ports and addresses.
- Key locations.
- Channel ID.
- Funding key (infra sources it from the PoWClaim in the blockchain `keystore.yaml`).
- Gossip bootstrap peers.

**Data dir.**

- One `--data-dir` with a fixed internal layout.
- Explicit per-file flags only where infra needs to point elsewhere (keys).

**Secrets.**

- Never in the config file. Separate files only.
- Keys are generated by infra and stored in Vault. They are never shared over chat.
- Generating keys during config creation is only a usability shortcut.

**Debuggability.** The first log line is the full loaded config, with secrets redacted. A `/config` endpoint is an alternative.

**Health and metrics.**

- `/ping`: cheap and static.
- `/health`: expensive, may check dependencies, returns JSON status.
- `/metrics`: Prometheus.
- These go on a separate HTTP port from the RPC. Infra can reverse-proxy and hide HTTP endpoints; it can't do that for JSON-RPC.
- Checks run at two levels: Docker (per container) and Consul (per host, needs the port mapped).

**Logs.**

- Always JSON, for Logstash and Kibana.
- Severity discipline:
  - `error` means someone must dig in. `warn` means worth investigating.
  - Something that never needs investigating is not a warning.
  - Something that is really a state signal should be a metric, not a log line.

**Metrics.**

- Keep label cardinality low. No error strings, peer IDs, IPs or ports in labels.
- Bucket errors instead (`type="timeout"`, and so on).
- Name metrics as `service_subsystem_measurement_unit`, per [Prometheus naming](https://prometheus.io/docs/practices/naming/).

**Compose.**

- Every host port and every secret-volume source path is overridable with `${VAR:-default}`. Otherwise a path change in our repo silently breaks infra's Vault-to-file wiring.
- Per-environment env files at the repo root: `.env.local` (also the `.env` default), `.env.devnet`, `.env.testnet`.

**Bootstrap peers.**

- The sequencer count varies (1, 4, …).
- A repeatable flag that daisy-chains the peers works, and avoids generating the peer list at runtime:

  ```
  --bootstrap-peer=sequencer_service_0:13040
  --bootstrap-peer=sequencer_service_1:13040
  ```

**Indexer.** It is effectively a sequencer without a key. Merging it into the sequencer is in progress in a separate PR. Don't invest in indexer-specific CLI work; the merged binary follows the conventions here.

**Blockchain (L1).** Infra asked for a configurable, longer bootstrap duration. That belongs to logos-blockchain, not this repo.

## How infra deploys today (infra-logos)

- **Templating.** Ansible renders one docker-compose file per host from `docker-compose.yml.j2`. It covers the blockchain node (an `init` container runs `init-config`/`update-config` with flags), the indexer, N sequencers and the explorer. Ports are `base + i` per sequencer.
- **Copied configs.** Infra keeps its own copy of our JSON configs per env (`files/lez/{devnet,devnet-classic,testnet,testnet-legacy}/`). Ansible then deep-merges overrides into them:
  - `home`
  - `bedrock_config.{channel_id, funding_key, node_url}`
  - `gossip.listen_addr` and `bootstrap_peers` (generated from `base port + i` and the host's public IP)

  This override set is exactly the meeting's "overrideable" list. Everything else in those files is the static part we should ship.
- **Keys.** They come from Vault and are written to `conf/sequencer/seq-N/bedrock_signing_key` with mode `0600`. That file is then bind-mounted into `/var/lib/sequencer_service/`, inside the data volume, because the key path is hardcoded to `<home>/bedrock_signing_key`.
- **Version branches.** The role handles old LEZ versions: a `signing_key` config field and a `--signing-key` flag that the current binary doesn't have.
- **Health.**
  - Defaults already declare `lez_{sequencer,indexer}_health_path: '/health'`, but nothing uses it yet. They expect it.
  - The sequencer Docker check POSTs `{}` with `curl -sf`.
  - Consul uses TCP and `nc -z` checks.
  - The per-sequencer metrics Consul services are copy-pasted for exactly four sequencers.

Things to raise with infra:

- `vars/lez/testnet.yml` sets `lez_sequencer_image`, but the role reads `lez_sequencer_cont_image`. Testnet therefore runs the default (non-mdns) image, which may or may not be intended.
- Every infra indexer config, testnet included, sets `allow_chain_reset: true`. On a chain mismatch the indexer wipes its store and reindexes.
- devnet-classic runs the indexer on port 18779, but the image healthcheck probes 8779. Both healthchecks need to follow the configured port. That's a point in favour of env vars inside the container, or of the ops port below.

## Target shape

| What | How |
|---|---|
| Tuning (`max_num_tx_in_block`, timeouts, mempool, …) | Default config file baked into the image at `/etc/sequencer_service/sequencer_config.json`. `--config` defaults to it. All values are explicit; no hidden serde defaults. |
| Genesis (`genesis` actions, `channel_params`, `cross_zone`) | Embedded per network (`--network`), with `--genesis-file` to override. channel_params are network constants: testnet uses 25e9/900/150/240, our local default is 149/300/25/100. |
| Channel ID, funding key, bedrock URL | `--channel-id`, `--funding-public-key`, `--bedrock-url` |
| Listen addresses | Full `host:port` values, following #981: `--rpc-listen-address`, `--metrics-listen-address` (later the ops port: `/ping` `/health` `/metrics`), `--gossip-listen-address` (a fixed port, not `udp/0`) |
| Bootstrap peers | Repeatable `--gossip-bootstrap-peer host:port`, expanded to `/dns/<host>/udp/<port>/quic-v1`, or `/ip4/...` for an IP. A full multiaddr is passed through as is. |
| Data and keys | `start <home>` with the fixed layout from #979: `sequencer_config.json`, `channel_signing_key`, `bedrock_funding_public_key`. `--config` and `--channel-signing-key-file` point outside it, so infra can mount secrets outside the data volume. Only `setup` creates keys; `start` refuses to run without one. |
| Secrets | Files only. Never in the JSON. `bedrock_config.auth.password` is still plaintext JSON; nobody uses auth today, so a `--bedrock-password-file` waits until someone does. |
| Logs | `--log-format json\|text`. The image sets `json`. Can be done with an `env_logger` custom format, no new dependency. |

**Conventions.**

- Every `start` flag `--kebab-name` has `env = "SEQUENCER_KEBAB_NAME"` (`EXPLORER_` for the explorer). A unit test walks `Args::command()` and asserts the mapping.
- No bare `--port`. Addresses are `*-listen-address` with a full `host:port`.
- Strict parsing: `deny_unknown_fields`.
- First log line is the redacted effective config.
